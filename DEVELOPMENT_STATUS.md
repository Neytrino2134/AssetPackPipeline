Модели со статусом skipped не создают backup. Dirty target packages блокируют старт и повторно проверяются перед обработкой модели. Запись о результате сохраняется после каждого завершённого ассета и обновляется на финальной проверке общего контента. Стабильный master/helper не сохраняются при каждом повторе.

Задачи import/settings_update теперь сохраняют замороженный профиль в своей папке Runs. После перезапуска статус старой running-задачи становится interrupted. resume_job использует её сохранённый профиль, проверяет проект, версии, хэши исходников и выбранный MeshInfo mapping; создаёт новый run_id с resumed_from. Вкладка «Очередь» и MCP list_runs/resume_job показывают и продолжают задачи. Готовый passed run повторно не запускается через resume.

## Особенности UE 5.8.3, учтённые в реализации

- SetMaterialInstanceTextureParameterValue в установленном исходнике возвращает false без изменения bResult, хотя устанавливает значение. Проверяем фактический параметр.
- Collision edits пересобирают render data. Сначала сохранить и дождаться сборки, затем назначить screen sizes и сохранить повторно; иначе read-back давал нули.
- В PythonScript commandlet StaticMeshEditorSubsystem не создаётся автоматически: создаём отдельный transient объект для вызовов API.
- Native module build остановился на отсутствующем NetFxSDK до компиляции нашего кода. Рабочий плагин не требует C++; прототип вынесен в Docs/NativeModulePrototype. Не считать C++ build пройденным.
