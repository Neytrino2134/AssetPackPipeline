# 0.24.0 — два интерфейса одного пайплайна

В Unreal: Tools / Инструменты → Asset Pack Pipeline:

- «Открыть Unreal UI (Slate)…» — нативная вкладка редактора.
- «Открыть Custom UI (отдельное окно)…» — оформление и вкладки прежнего интерфейса,
  отдельный процесс Epic Python с обычным Tk mainloop. Внутри процесса Unreal Tk не загружается.

Повторный запуск Custom UI при уже открытом окне поднимает его; второй процесс
не создаётся. Закрытие Custom UI не останавливает выполняющийся импорт и последующие
этапы серверной последовательности. Откройте окно снова для получения состояния.
Для остановки используйте кнопку «Остановить», а не закрытие окна.
При закрытии/перезапуске Unreal старое окно сообщает потерю соединения; запустите
новый Custom UI через меню нового редактора. Несохранённые поля окон независимы.

Общие: active_profile.json, папка Saved/AssetPackPipeline, результаты, run_id,
API импорта, очередь и серверный guided.Session. Профиль, изменённый в другом окне,
нужно явно загрузить; несохранённые поля автоматически не перезаписываются.
Второй интерфейс не начинает другую последовательность, пока первая активна.
Ключ OpenAI хранится тем же ai_settings; сохранённые настройки общие. Ключ на время
сеанса принадлежит процессу, последующие изменения session-only ключа в другом
окне не синхронизируются автоматически. Live OpenAI здесь не проверялся.

## Локальная связь

Файловая очередь Saved/AssetPackPipeline/CustomIPC, без TCP и HTTP listener.
Запросы и ответы подписаны HMAC-SHA256, имеют session/id/срок действия. Повторный
идентификатор не выполняется повторно. Запись атомарная; размеры ограничены.
Одноразовый bootstrap передаёт секрет сеанса через stdin дочернего процесса,
не через командную строку и не через файлы проекта. Ключ API не входит в RPC.
Нет eval/exec, произвольных методов Unreal или shell-команд. Только allowlist API.
Все операции с Unreal исполняются Slate post tick на editor thread с защитой
от повторного входа. GUI использует собственный обычный mainloop.
Сервер прекращает пустой polling после выхода GUI; последовательность задач
остаётся на независимом native_bridge tick.

Это канал между процессами одного пользователя, не защита от вредоносного кода
с правами этого же Windows-пользователя. Папка проекта должна быть доверенной.
С версии 0.24.1 старт окна и автоматический опрос не ждут Unreal в потоке Tk:
один фоновый запрос получает readiness/guided/report, UI читает готовый снимок.
Интервал запросов — 0,5 секунды во время задачи и 2 секунды в простое.
Явные команды пользователя пока синхронные: длинный анализ/копирование может
временно блокировать Custom UI. Таймаут 120 секунд не повторяет
команду автоматически: операция могла начаться, сначала проверьте очередь.

## Проверки

119 unittest, включая неверную подпись, изменение данных, просроченные/повторные
запросы, предел размера и запрет произвольного Python.

Интеграция в настоящем UE 5.8.4 / изолированном HostProject:

1. Создано реальное Custom Tk-окно отдельным процессом; подтверждён RPC handshake.
2. Через клиент запущена серверная подготовка одного контейнера LOD/MID.
3. Завершён только тестовый GUI-процесс, Unreal остался жив и продолжил очередь.
4. Создан новый GUI-процесс, он подключился к тому же редактору.
5. Обе версии меша прошли проверку; 7 собственных тестовых ассетов удалены с backup.
6. В Custom UI: tkinter=true, unreal=false. В Unreal: tkinter=false.

См. Verification024.json. Это не длительный тест ручного IME/Alt-Tab; встроенный
Slate ранее проверен отдельно. Основной пользовательский Content не изменялся.
Установка: закрыть Unreal, распаковать актуальный архив поверх папки плагина,
сохранить локальный каталог .git, открыть проект.
Native DLL совпадает с проверенной сборкой 0.23.0; изменения этой версии — Python
adapter/launcher/menu. Бинарник для UE 5.8.4 Win64, другие версии требуют пересборки.
