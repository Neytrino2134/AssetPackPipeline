# Custom UI 0.24.1 — отзывчивость окна

Причина задержек: автоматический таймер выполнял несколько синхронных RPC
последовательно в потоке Tk. При занятом или фоновом Unreal окно ждало ответ,
откладывая обработку ввода и перерисовку. До запуска mainloop также ожидался RPC.

Изменения:

- Окно создаётся до подключения, без синхронного запроса к редактору.
- Один фоновый поток запрашивает общий снимок состояния. Он не обращается к Tk
  или UObject; все операции Unreal остаются в editor thread серверного процесса.
- UI применяет только новые снимки, не перестраивает прежние таблицы и не меняет
  состояние всех кнопок каждые 100 мс. Применение отчёта не вызывает RPC.
- Активная задача опрашивается раз в 0,5 секунды, простой — раз в 2 секунды.
  Одновременно выполняется максимум один автоматический запрос.
- Закрытие окна сигнализирует остановку фонового опроса. Поток daemon не мешает
  выходу процесса, даже если редактор не отвечает.

Проверено 31.10.2026 в UE 5.8.4 / Win64, изолированном HostProject с NullRHI:

- 121 unittest, включая чтение UI-кэша во время заблокированного ответа сервера.
- Настоящие отдельные Tk-процессы: создание виджетов 0,218 секунды.
- Искусственная задержка ответа Unreal на 2 секунды при повторном подключении:
  152 измерения таймера UI, p95 32 мс, максимум после старта 47 мс.
- Импорт LOD/MID, выход первого GUI, подключение второго GUI и завершение задачи
  прошли; 7 собственных тестовых ассетов очищены с backup.
- Tk не загружается в Unreal, Unreal не импортируется в GUI.

Это измерение обработки событий, не ручной тест перетаскивания окна/IME и не
измерение GPU-композиции рабочего редактора. Явные команды анализа/копирования
пока синхронны; исправление касается старта и постоянного фонового опроса.
Метрики не включают холодный запуск самого Python до создания окна.

Воспроизведение: Tools/smoke_custom_ui.py только в изолированном HostProject
внутри Saved. Результат: Docs/Verification0241.json. DLL не менялась.
