# Обновления без Git — 0.26.0

Установить 0.26.0 вручную в проект `Plugins/AssetPackPipeline`, закрыв Unreal.
На клиентских устройствах не нужны Git, GitHub Desktop, pip или отдельный Python:
используется Python из Unreal. Поддерживается Windows / Win64.

## Настройки

Инструменты / Tools → Asset Pack Pipeline → «Настройки и обновления…».
Такая же кнопка есть в Custom UI и Unreal Slate. Окно настроек запускается
отдельным процессом; Tk в Unreal не загружается.

Поля: публичный GitHub-репозиторий `owner/name`, проверка при запуске редактора,
«Проверить сейчас», «Скачать и установить». По умолчанию репозиторий
`Neytrino2134/AssetPackPipeline`, автоматическая проверка включена.
Настройки сохраняются локально в `%LOCALAPPDATA%/AssetPackPipeline/update-settings.json`,
отдельно от профилей и поставок ассетпаков. Токен GitHub не нужен.

Проверка и загрузка выполняются фоновым потоком. При наличии новой версии
обновляется подпись кнопки Custom UI и пункта меню Unreal; также появляется
сообщение в Output Log. В автоматических unattended/commandlet-тестах проверки нет.
Проверяется последний стабильный опубликованный Release; draft/prerelease пропускаются.
Отсутствие релиза, недоступная сеть, несовместимость и текущая версия имеют
разные состояния. Более старые версии не устанавливаются.

## Установка

1. Нажать «Скачать и установить» и подтвердить загрузку из показанного репозитория.
2. Дождаться сообщения «Скачано и проверено».
3. Закрыть Unreal и другие редакторы, использующие ту же папку плагина.
   Проект не закрывается автоматически; сохраните свою работу обычным способом.
4. Дождаться сообщения «Обновление установлено» в отдельном окне и открыть проект.
   Не нажимать быстрый перезапуск редактора до завершения установки.

Проверяются версия, точная версия Unreal, BuildId модулей, размер и SHA256 архива,
пути внутри ZIP, наличие DLL и соответствие descriptor/manifest. Источник —
настроенный публичный GitHub Release по HTTPS; архив исходников GitHub не подходит.
Это доверие владельцу указанного репозитория, не отдельная цифровая подпись автора.

После скачивания запускается скопированный в Saved установщик. Он ждёт выхода
конкретного процесса Unreal, повторно проверяет ZIP, затем заменяет каталог плагина.
Прежняя версия целиком остаётся в `Saved/AssetPackPipeline/Updates/jobs/<id>/backup`.
При ошибке размещения новой версии старый каталог возвращается обратно.
Результат/ошибка — `result.json` рядом с backup. Ожидание закрытия — до двух часов.
Проектные Content, Config, профили в Saved и пользовательские API-ключи не заменяются.
Изменения внутри самого плагина сохраняются только в backup.

Автоустановка отключена для рабочего checkout с `.git`: используйте GitHub Desktop.
Поддерживается установка непосредственно в `Project/Plugins/AssetPackPipeline`;
глобальные Engine-плагины и вложенная раскладка требуют ручной установки.
Для ручного отката закройте редактор, сохраните текущую папку плагина отдельно и
восстановите backup на её место. Установщик не удаляет старые backup автоматически.

## Как публиковать обновление

Одного Push origin в GitHub Desktop недостаточно: нужны готовые бинарные файлы.

1. Повысить версию в `.uplugin` и Python `__version__`, собрать и проверить плагин
   для нужной версии Unreal.
2. Запустить `Tools/package_pipeline.py --binary-source <каталог Win64 DLL и .modules>
   --engine-version 5.8.4` через Python из Unreal.
3. Получатся `Releases/AssetPackPipeline-<версия>.zip` и
   `Releases/AssetPackPipeline-update.json`. Манифест содержит SHA256 этого ZIP,
   версию движка, BuildId, Win64 и имя установочного файла.
4. Сохранить коммит и отправить main на GitHub. На странице Releases создать
   стабильный Release с тегом `v<версия>` на нужном коммите.
5. Прикрепить оба файла из одного запуска упаковщика и опубликовать Release.
   Системные Source code.zip / tar.gz не заменяют установочный ZIP.

Текущая схема — один целевой Win64/UE BuildId на Release. Если нужны несколько
версий Unreal, потребуется расширение манифеста под несколько установочных архивов.
Не менять ZIP после генерации манифеста. Исходные изменения без релиза на другие
компьютеры не устанавливаются.

## Проверка

139 unittest: числовое сравнение версий, несовместимый BuildId, отсутствие релиза,
ограничение источника, SHA256, traversal, Windows-имена, .git в ZIP, защита checkout,
отказ downgrade, backup, сохранность Content и rollback при блокировке.

Сборка Native Slate — успешна. В настоящем UE проверены engine context/BuildId,
открытие/закрытие Slate и отсутствие Tk внутри редактора.
Отдельное окно Tk запущено с тестовым ответом о новой версии, кнопка установки
доступна. Проверен отдельный установщик с реальными архивами 0.25.3 → 0.26.0,
ожидающий выхода отдельного Python-процесса, имитирующего время жизни редактора.
Это не закрытие пользовательского Unreal и не загрузка опубликованного релиза.
Публичный API проверен: на момент реализации Releases ещё нет; end-to-end загрузка
с GitHub возможна после первого опубликованного релиза. См. Verification0260.json.
